# AGENTS.md — app

These instructions add to the repository root `AGENTS.md`; they never relax it. Read the root file first.

## What this app is
- Purpose: the Platform Core dashboard as an installed app on desktop (Windows, macOS, Linux) and mobile (Android, iOS). A thin host for `packages/ui`: the screens are the same ones the web app shows.
- Kind: desktop client and mobile client
- Stack: Vue 3 and Vite 8 inside Tauri 2 (ADR-006), TypeScript (strict), Vuetify 4 through `packages/ui`; the Rust shell in `src-tauri/` is a member of the root Cargo workspace. Details in docs/TECHNICAL.md, Components.
- Depends on: `packages/ui` (layout shell, screens and the configured api client), and through it `packages/api-client-ts` and the api (`apps/api`) over HTTP.

## Commands
Use this app's row in the README [Commands](../../README.md#commands) table. Run them from the repo root with a filter: `pnpm --filter app tauri dev`, `pnpm --filter app test`, `pnpm --filter app typecheck`, `pnpm --filter app build` (Vite only), `pnpm --filter app tauri build` (unsigned desktop build). The Rust shell is checked with the workspace: `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --all --check`.

The Vite dev server always uses port 1420 (`strictPort`; `tauri.conf.json` `devUrl` points at it). Start the api first (README) if you want the status screen to show healthy; until the api allows this app's origin with CORS (TASK-015), the status screen shows offline.

### Android
`tauri android` needs these variables in your shell (set them for the command only; nothing in the repo depends on them):
- `ANDROID_HOME`: the Android SDK, e.g. `%LOCALAPPDATA%\Android\Sdk` on Windows.
- `NDK_HOME`: an NDK inside it, e.g. `$ANDROID_HOME/ndk/27.0.12077973`.
- `JAVA_HOME`: JDK 17 or newer, e.g. Android Studio's bundled `jbr` folder (an older `java` on `PATH` makes Gradle fail).
- The Rust Android targets: `rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android`.

Then `pnpm --filter app tauri android dev` (emulator or device) or `pnpm --filter app tauri android build --debug --apk` (unsigned; the APK lands in `src-tauri/gen/android/app/build/outputs/apk/`). Without `--target` it builds all four ABIs, which is slow; add `--target aarch64` for phones and most emulators on ARM, or `--target x86_64` for an x86 emulator. The first Gradle run downloads Gradle and may install the Android SDK platform named by `compileSdk`. An emulator reaches the computer's api at `10.0.2.2`, not `127.0.0.1`; set `VITE_API_BASE_URL` and the CSP `connect-src` to match.

### iOS
`tauri ios init`, `dev` and `build` need macOS with Xcode. The iOS project (`src-tauri/gen/apple`) has not been generated yet; whoever first works on iOS runs `pnpm --filter app tauri ios init` on a Mac and commits the result.

## Layout
- `src/main.ts` creates the Vue app and installs `createPlatformUi` from `ui` with the api base URL; `src/App.vue` renders `<AppShell>` and `<StatusScreen>` from `ui`. `src/config.ts` reads the public build configuration.
- `src-tauri/` is the Tauri shell (crate `app`, library `app_lib`): `src/lib.rs` builds the app (`run()`), `src/main.rs` calls it on desktop, `tauri.conf.json` holds the window, CSP and bundle settings, `capabilities/default.json` the permissions.
- `src-tauri/gen/android/` is the Android project generated by `tauri android init`. It is committed (the Tauri docs treat it as source) and may be edited for Android-specific settings; `src-tauri/gen/schemas/` is regenerated on every build and is gitignored.

## Rules for this app
- Configuration: every variable in `.env.example` ships to users and is public; never put secrets here. Only `VITE_*` variables reach the app, and they are compiled in at build time.
- No screens, components or api calls in this app: they belong in `packages/ui` (root AGENTS.md, principles 18 and 19). This app holds only the entry point, routing and layouts when they come, and platform-specific code.
- Tauri permissions: `capabilities/default.json` grants only `core:default`. Adding a plugin (shell, file system, HTTP, …) or a permission needs a reason in the PR and review; prefer fetch from the web view over Tauri commands for api calls.
- Content Security Policy (`tauri.conf.json`, `app.security.csp` and `devCsp`): `connect-src` allows only the app itself, Tauri IPC and the api (`http://127.0.0.1:18080` locally). When a build points `VITE_API_BASE_URL` somewhere else, add that origin to `connect-src` (for example with `tauri build --config <file>`); never use a wildcard. `style-src` keeps `'unsafe-inline'` (with `dangerousDisableAssetCspModification: ["style-src"]`) because Vuetify writes its theme into a `<style>` element at runtime; scripts stay `'self'` only.
- Any Tauri command added to `src-tauri` gets unit tests (`cargo test -p app`).
- Directories not to edit by hand: `src-tauri/gen/schemas/` (generated, gitignored), `dist/` and the workspace `target/` at the repo root (build output; desktop installers land in `target/release/bundle/`). Regenerate the icons with `pnpm --filter app tauri icon <source.png>` rather than editing them one by one.
- Signing: builds made here are unsigned. Signing certificates, keystores and the updater key are release secrets (docs/DEPLOYMENT.md); never create, store or use them in this folder or in an agent session.

## Release
Versioned separately; tags are `app-vX.Y.Z`. Record user-visible changes in this folder's CHANGELOG.md. Release steps are in docs/DEPLOYMENT.md; signed builds for mobile and desktop apps run in `.github/workflows/release.yml`, never on a developer machine or in an agent session.
